==================================================

The audit found:

unallocatedCents =
jar target - named goal targets

surplusCents =
saved principal remaining after filling named goals

This means surplusCents can contain BOTH:

- principal filling the unnamed/unallocated target portion
- true over-target principal

That naming is ambiguous.

Do NOT change financial accounting.

Choose one clean API semantic.

Preferred approach:

Keep:

unallocatedTargetCents =
max(0, jarTarget - activeGoalTargets)

Add / expose:

savedTowardUnallocatedCents =
min(
  max(0, savedPrincipal - activeGoalTargets),
  unallocatedTargetCents
)

overTargetCents =
max(0, savedPrincipal - jarTarget)

Then avoid exposing ambiguous `surplusCents` as a user-facing concept.

If backwards compatibility requires keeping surplusCents:
document it as:
"saved principal remaining after named goals"
and do not label it "over target."

Mobile should use:

- Unallocated target
- Saved toward unallocated
- Above Jar target

as separate concepts where relevant.

No new persisted table is needed.
