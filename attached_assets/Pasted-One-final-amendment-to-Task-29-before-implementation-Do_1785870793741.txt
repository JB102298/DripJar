1. REPLACE THE CLOSED-FORM GROSS-UP FORMULAS

Remove the current closed-form card and ACH formulas.

They currently overestimate some values.

For example:

baseCents = 20,600 ($206.00)

CARD:
The correct minimum processing fee is 646 cents.

providerFee(21,246):
halfUp(21,246 × 290 / 10,000) + 30
= 616 + 30
= 646

Therefore:
processing fee = $6.46
total charge = $212.46

ACH:
The correct minimum processing fee is 166 cents, NOT 167.

providerFee(20,766):
halfUp(20,766 × 80 / 10,000)
= 166

Therefore:
processing fee = $1.66
total charge = $207.66

Use a deterministic integer fixed-point solver instead of a fragile closed-form equation.

Recommended algorithm concept:

function computeGrossedUpProviderFee(baseCents, paymentMethodType) {
  validateSafeInteger(baseCents);

  let feeCents = 0;

  for a bounded number of iterations {
    const requiredFee =
      computeStripeFeeOnCharge(
        baseCents + feeCents,
        paymentMethodType
      );

    if (requiredFee <= feeCents) {
      return feeCents;
    }

    feeCents = requiredFee;
  }

  throw new Error("Provider fee gross-up did not converge");
}

computeStripeFeeOnCharge must use integer cents:

CARD:
halfUp(totalCents × 290 / 10_000) + 30

ACH:
min(
  halfUp(totalCents × 80 / 10_000),
  500
)

The solver starts from zero and monotonically approaches the minimum fee that covers the provider fee.

Add a minimality invariant to tests:

For returned fee P:

providerFee(base + P) <= P

AND, when P > 0:

providerFee(base + P - 1) > P - 1

That proves P is the MINIMUM sufficient whole-cent fee, not merely a sufficient fee.
